# iPhone<->Redmi protocol (WebSocket, BLE) and the diagnostics, health and OTA docs; extension points for MetricKit upload, more client_status fields and a Redmi->iPhone health alert

## Summary
The only protocol doc is RedmiGateway/docs/PROTOCOL.md, which describes "Phone Bridge protocol (version 2)". RedmiGateway/pre_unlock_snapshot/docs/PROTOCOL.md is an outdated v1 copy. PROTOCOL.md has no entry for the telemetry messages the code actually uses: client_log, client_status, contact_info/resolve_contact, the shapes of ack and error, and the appVersion/appBuild fields in hello and auth. The code is therefore the real contract.

Compatibility works by tolerance, not by version bumps:
- Unknown fields are ignored on both sides: Android reads them with org.json opt*, iOS with Swift Decodable or JSONSerialization.
- An unknown type sent iPhone->Redmi gets a sealed {"type":"error","code":"unknown_command","command":<type>}. iOS only logs it.
- An unknown type sent Redmi->iPhone is silently ignored (`default: break`).
- Earlier features (calls, holdCurrent, redundancy, request_iphone_audio) were all added without bumping the protocol. Tests pin PROTOCOL=2 and bind the websocket AAD "phonebridge-ws-2" to that number. A bump would mark the app as DEGRADED on older iPhones and break those tests.

The hard limits apply to iPhone->Redmi traffic:
- GatewayWebSocketServer.onMessage silently drops any raw frame longer than 16,384 chars before decrypting it. There is no log and no reply.
- The sealed envelope is {"t":"s","c":N,"d":base64(ciphertext||16-byte tag)}, so the largest inner JSON that gets through is about 12,250 UTF-8 bytes.
- The Java-WebSocket 1.5.6 Draft is set to MAX_FRAME_BYTES = 64 KB. Disassembling the jar shows that a frame above that throws LimitExceededException(1009) and the library closes the connection.
- A 20-60 KB MetricKit JSON is therefore either dropped silently (plaintext up to about 49 KB) or kills the control socket with 1009 (plaintext above about 49 KB). If the close happens while the Redmi is preparing the iPhone handover, CallAudioRelay.onControlLinkLost releases the audio back to the Redmi.
- Redmi->iPhone has room: iOS receives up to 1 MiB.

The iOS telemetry is fire-and-forget:
- send() ignores the completion result.
- flushTelemetry marks lines as delivered with no ack.
- A batch is 40 lines from a 300-line ring.
- Everything runs only while the app is authenticated. The usual resting state (app in background, socket closed) sends nothing.

client_status:
- iOS sends 7 keys.
- Android writes only the keys in its STATUS_KEYS whitelist (12 names, 5 of which iOS never fills). Any new field is silently discarded until it is added to that list.
- IphoneDiagnostics truncates each line to 4,000 chars and rotates at 512 KB, so a large payload cannot go through record().

BLE cannot carry diagnostics:
- The control characteristic accepts only answer, reject, hangup, ringing_ack and mtu, each sealed with a seq/time freshness check.
- State notifications are chunked into pieces of 20 bytes or less, and iOS drops a half-built frame after 1 s.

Health today is local to the Redmi:
- HealthCheck/HealthReporter post an Android notification once per service start, which nobody sees in the pocket-use scenario.
- The iPhone sees problem codes only when it pulls them with the `diagnostics` command (diagnostics_result.problems).

No MetricKit code exists anywhere in the repo.

## Facts
- PROTOCOL.md describes 'Phone Bridge protocol (version 2)'. Its channels are the WebSocket on 8787 (control), UDP on 8791 (media), the BLE GATT service A67D0001-... and Bonjour _redmigateway._tcp with TXT v=2. (RedmiGateway/docs/PROTOCOL.md:1)
- Compatibility rule in the doc: hello announces protocol and minProtocol. minProtocol>2 makes the iPhone INCOMPATIBLE ('update the iPhone app'). protocol<2 is INCOMPATIBLE ('update the Redmi app'). protocol=2 is SUPPORTED. protocol>2 with minProtocol<=2 is DEGRADED. Protocol 1 clients are accepted only until the first keyed pairing exists. (RedmiGateway/docs/PROTOCOL.md:31)
- The sealed WebSocket frame is {"t":"s","c":counter,"d":base64}, with AES-GCM under derive(S,"ws") and AAD "phonebridge-ws-2". The nonce is a direction tag (C2S\0 or S2C\0) plus an 8-byte counter. Counters must strictly increase, and unsealed frames after authentication are ignored. (RedmiGateway/docs/PROTOCOL.md:90)
- The PROTOCOL.md command table lists get_state, dial, hold_call, swap_calls, merge_calls, answer/reject/hangup, dtmf, ringing_ack, audio_start/stop, audio_to_redmi, send_sms, sync, diagnostics (-> diagnostics_result, 'no numbers, message text or keys'), unpair, push_token and push_alert_token. It does NOT list client_log, client_status, contact_info/contact_resolved, lab or the legacy aliases. (RedmiGateway/docs/PROTOCOL.md:160)
- The error codes documented in PROTOCOL.md are unauthorized, unknown_command, internal_error, no_call, audio_busy and lab_disabled. The lab hooks need the adb LAB_MODE broadcast and expire after 2 hours. (RedmiGateway/docs/PROTOCOL.md:241)
- The pre_unlock_snapshot PROTOCOL.md is an outdated v1 document ('Redmi Gateway WebSocket Protocol (v1)') and must not be edited by mistake. (RedmiGateway/pre_unlock_snapshot/docs/PROTOCOL.md:1)
- Android declares PROTOCOL = 2 and MIN_PROTOCOL = 1. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:62)
- Android STATUS_KEYS whitelist for client_status: appVersion, appBuild, appState, callkit, audio, mic, notify, ble, battery, thermal, lowPower, network. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:67)
- The WebSocket server is built with Draft_6455(emptyList(), MAX_FRAME_BYTES) and MAX_FRAME_BYTES = 64*1024. The comment says onMessage already ignores anything above 16 KB. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:48)
- The Java-WebSocket library version is 1.5.6. Disassembling the jar with javap shows that Draft_6455.translateSingleFrameCheckLengthLimit and checkBufferLimit throw LimitExceededException("Payload limit reached.", maxFrameSize), which carries close code 1009. WebSocketImpl.decodeFrames catches it and calls close(e). An over-64 KB frame, including one assembled from continuation fragments, closes the connection. (RedmiGateway/android/app/build.gradle.kts:71)
- hello contains type, device, protocol, minProtocol, gatewayId, nonce, paired, addresses, appVersion (VERSION_NAME string) and appBuild (BuildConfig.VERSION_CODE, a JSON number). (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:137)
- onMessage silently returns when the raw frame length is above 16,384 chars. This check runs before JSON parsing, before authentication and before unsealing, and nothing is logged or replied. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:197)
- Before authentication only pair and auth are accepted. Any other type gets a plain {type:error, code:unauthorized}. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:203)
- After authentication a frame whose t is not 's' is dropped silently. A frame that fails to unseal is dropped with the log 'Dropped a sealed frame that failed authentication'. An exception in dispatch makes the Redmi reply error internal_error. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:211)
- The auth handler stores the iPhone's appVersion and appBuild from the auth frame on the Peer (json.optString). The Redmi can therefore feature-detect the iPhone build per connection. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:327)
- onAuthenticated sends calls (protocol>=2 only), the current call, audio_state, call_waiting and queued SMS results. This is the natural place to push the current health state on link-up. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:352)
- The client_log handler sends no reply. It labels lines iPhone[appVersion/appBuild], records 'telemetry dropped N lines' when dropped>0, and stores at most MAX_LINES_PER_FRAME lines from the 'lines' array through IphoneDiagnostics.record. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:437)
- The client_status handler writes one 'iPhone-status' line containing only the STATUS_KEYS keys that are present and non-blank. Any other key is discarded silently. Values are written with toString(), so any JSON type is tolerated. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:452)
- Any unknown authenticated type is answered with error {code: unknown_command, command: <type>}. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:497)
- The `diagnostics` command replies with DiagnosticsReport.build(context) plus type diagnostics_result. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:432)
- The `lab` command works only when LabMode.enabled is set and otherwise returns error lab_disabled. op 'stats' returns a CallAudioLab snapshot, other ops go to CallAudioLab.handle, and the reply type is lab_result. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:476)
- Precedent for adding Redmi->iPhone types without a bump: the comment on callsMessage says 'old iPhone builds ignore the type'. The calls message goes only to peers with protocol>=2. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:662)
- send() seals and queues under synchronized(peer), so counters leave in order. Send errors are swallowed by runCatching. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:790)
- The 'never pay mobile data' precedent: audio redundancy is never enabled on a remote (VPN) link because 'a mobile data link must not pay for it'. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:548)
- onClose records an 'iPhone-link closed code=... verdict=...' line to IphoneDiagnostics. If the closing socket owned the audio, it calls CallAudioRelay.onControlLinkLost('iphone_disconnected'). (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:151)
- onControlLinkLost keeps the iPhone audio only if media is running, the owner is IPHONE and iPhone PCM arrived within silenceLimitMs. In every other case, for example while PREPARING_IPHONE, it calls releaseAll and the call audio returns to the Redmi. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/audio/CallAudioRelay.kt:451)
- Only the String overload onMessage(conn, message: String) is implemented. There is no binary (ByteBuffer) handler, so binary frames from the iPhone are ignored. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:194)
- The Kotlin SecureChannel.seal output is {"t":"s","c":N,"d":base64(ct||tag)} with no nonce on the wire. open() rejects counter <= lastReceived. A frame that is dropped before open() does not advance lastReceived. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/security/SecureChannel.kt:22)
- Derived size limit, iPhone->Redmi: raw length = 21 + digits(c) + 4*ceil((P+16)/3). The 16,384-char gate allows inner plaintext P of about 12,250 UTF-8 bytes or less. The 64 KB frame limit is exceeded when P is above about 49,100 bytes. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/security/BridgeCrypto.kt:18)
- IphoneDiagnostics writes iphone-diagnostics.log (and iphone-diagnostics.1.log) under getExternalFilesDir("diagnostics"). Limits: MAX_BYTES 512 KB with a single rotation, MAX_LINE_CHARS 4000 (longer lines get '...(truncated)'), MAX_LINES_PER_FRAME 200. Lines are 'MM-dd HH:mm:ss.SSS tag: text', written on a single-thread executor. (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/journal/IphoneDiagnostics.kt:26)

## Extension points
- Android: add a new iPhone->Redmi type (e.g. ios_diagnostic) to the dispatch `when` (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:437): Add a branch next to client_log/client_status, before `else` at line 497. Wrap it in runCatching like those two so an internal_error is never sent. Reply with a small ack (e.g. {type:ack, action:ios_diagnostic, success, id}) so iOS can delete its persisted copy. An ack with an unknown action is a no-op on old iOS (GatewayConnection.swift:1047). Do the file I/O on IphoneDiagnostics' executor, not on the WebSocket thread.
- Android: the size gate that every new iPhone->Redmi message must pass (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:197): The gate checks the raw sealed length (16,384 chars) before unsealing, so it cannot be relaxed per type. Two options. (a) iOS chunks the payload into parts of about 10 KB or less of plaintext ({type:ios_diagnostic, id, part, parts, data}), which works with the current gate. (b) Raise this gate and MAX_FRAME_BYTES (line 58) together; old Redmis would still drop large frames silently. Any change must also log the drop instead of a silent return.
- Android: new optional client_status fields (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:67): Only keys in STATUS_KEYS are written. Add the new keys here, keeping the existing order because the comment says 'written in this order'. Alternatively, write unknown keys as a trailing extra=... section. Values go through toString(), so a nested JSON object prints as JSON. Keep the whole line under 4000 chars (IphoneDiagnostics.MAX_LINE_CHARS) and the frame under the 16 KB gate.
- Android: storage for large iPhone diagnostics (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/journal/IphoneDiagnostics.kt:52): record() truncates to 4000 chars, and the shared file rotates at 512 KB, so one 60 KB payload would push out about 12% of the log. Use a separate file or directory beside it (same getExternalFilesDir("diagnostics") resolution, own size cap and rotation). Write one short summary line through record() with the existing tag format 'iPhone[...]' so zil-izi.ps1 and teslim-kapisi.ps1 keep working.
- Android: Redmi->iPhone health alert emission (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/service/HealthReporter.kt:61): publish() is the single place health is evaluated, and GatewayService.reportHealth (line 285) calls it on every ACTION_START. Push the same problem codes (HealthCheck.kt:25-28) and the romChanged flag to authenticated protocol>=2 peers, using the pattern at GatewayWebSocketServer.kt:755/761. Also send the current state in onAuthenticated (GatewayWebSocketServer.kt:352) so an iPhone that was away gets it on link-up. Old iOS ignores unknown types. Use stable codes, not sentences, and dedupe so a message goes out only on change (AGENTS 8.1).
- Android: health alert when the iPhone has no socket (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/push/ApnsSender.kt:98): sendAlert(title, body, threadId, collapseId) is the existing out-of-band path, gated on alertsReady (line 59). ## Risks
- A 20-60 KB MetricKit JSON sent as one sealed frame never arrives. Up to about 49 KB of plaintext it is dropped silently at GatewayWebSocketServer.kt:197, with no log and no reply. Above that it trips Java-WebSocket's 64 KB limit and the Redmi closes the control socket with 1009. If iOS re-sends on every reconnect, this becomes a reconnect loop.
- A control-socket close while the owner is PREPARING_IPHONE, or while iPhone PCM is not flowing, makes CallAudioRelay.onControlLinkLost releaseAll. An oversized diagnostic sent during a handover would push the call audio back to the Redmi. Never send big diagnostics while a call or CallKit call exists.
- The existing client_log can already lose data silently. A 40-line batch whose lines average more than about 300 bytes exceeds the 16 KB gate and is dropped, and iOS still advances clientLogDelivered (GatewayConnection.swift:1667). The 'Previous run crashed: <full stack>' line from CrashTrace is the most likely trigger, and it is also cut to 4000 chars on the Redmi.
- On the iPhone, telemetry exists only while the socket is authenticated. The normal background state (socket closed after the grace) sends nothing, the timers do not run while suspended, and the ring holds 300 lines. DURUM's 'at most ~5 s loss' leaves out lines sent into a dying socket, because the send completion is ignored.
- New client_status keys are discarded silently by the Android STATUS_KEYS whitelist unless Android is updated in the same release train.
- An old Redmi answers a new iPhone type with error unknown_command. iOS logs 'Redmi error: unknown_command' and moves on. Without an ack-based design, iOS cannot tell whether the data was stored.
- Running a MetricKit payload through log() or sanitizeTelemetry corrupts it: the regex replaces long digit runs (addresses, offsets, timestamps) with '<numara>', which produces invalid JSON.
- Decoding the hello appBuild (a JSON number) as a Swift String? fails the whole HelloMessage decode, and the handshake stalls.
- Bumping PROTOCOL to 3 breaks ProtocolVersionTest (AAD bound to the version) and marks every current iPhone as DEGRADED. Precedent says add optional types and fields without a bump.
- Writing large payloads into iphone-diagnostics.log (512 KB, single rotation) pushes out the call evidence that zil-izi.ps1 and teslim-kapisi.ps1 rely on. Repeated health or status lines must be written only on change (AGENTS 8.1).
- Uploading diagnostics over the Tailscale/VPN link spends mobile data (IMMUTABLE_RULES Kural 5, GatewayWebSocketServer.kt:548-550 precedent). The upload must be gated on the iOS isRemoteLink check.
- BLE cannot carry diagnostics. Control accepts only 5 actions with a strict q/t freshness check that a bulk sender would disturb (shared lastControlSeq), and state frames are chunked at 18 bytes with a 1 s reassembly timeout.
- AGENTS 6.2 (one behaviour change per build) and DURUM's build-waste rule: the iOS diagnostics upload, the client_status additions and any audio change must ship in separate builds. TestFlight build 155 expires around 27.01.2027, so a new iOS build is needed anyway.
- There is a doc drift. DURUM-20261029.md:164 points to a non-existent RedmiGateway/docs/OTA-ONARIM-20261028.md, and PROTOCOL.md omits client_log, client_status, contact_info, resolve_contact, the BLE conf/wid/wn fields, the mtu action and heartbeat 0005.
