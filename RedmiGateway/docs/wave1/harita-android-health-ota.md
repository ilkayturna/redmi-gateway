# Android health checks, OTA/update handling, alerts, versioning, tests (RedmiGateway/android) plus the iPhone-facing paths those results can travel on

## Summary
Health checking is a one-shot check that runs each time the service starts. GatewayService.onStartCommand(ACTION_START) runs on boot, on MY_PACKAGE_REPLACED, on a START_STICKY restart and when the UI starts the service. It calls reportHealth(). That function records the ROM build string (Build.VERSION.INCREMENTAL|Build.DISPLAY) in UpdateWatch's prefs and then calls HealthReporter.publish. HealthCheck finds 4 problems: vendorFix, privApp, privilegedPermissions (CAPTURE_AUDIO_OUTPUT and CALL_AUDIO_INTERCEPTION only) and defaultDialer. The first 3 are audioCritical. When an audioCritical problem exists, the only proactive output is a high-priority notification on the Redmi itself (prefixed "ROM güncellendi." if the build string changed), plus a CallManager.log line in the Redmi's call diagnostics log.

Nothing is pushed to the iPhone: no WebSocket frame and no APNs alert. The iPhone sees problem codes only if the owner taps "Redmi'den rapor al" under Advanced settings. That returns DiagnosticsReport JSON whose "problems" array holds the codes, shown as raw text.

There is no periodic re-check. Nothing knows about org.lineageos.updater or any OTA or updater setting, and nothing warns before an OTA. Loss is detected only after the reboot into the new ROM. RepairKit only builds a zip in Downloads (apply.sh run from a PC in recovery). It cannot repair anything on the device by itself.

Versioning: versionCode/versionName are in app/build.gradle.kts, currently 217/"2.0.17". The convention seen in git is code = 200 + patch, bumped in the feature commit, with "(2.0.N)" in the commit subject.

Tests: 41 JUnit4 files with 376 @Test methods under app/src/test, run with ./gradlew :app:testDebugUnitTest. The last local run on 2026-10-28 had 376 tests and 0 failures. HealthCheckTest(10), UpdateWatchTest(5), InstallContractTest(6), RepairKitTest(13) and VendorFixPresentTest(7) cover health and OTA.

Permissions: the manifest has WRITE_SETTINGS (Settings.System only), POST_NOTIFICATIONS and the 4 privapp-allowlisted permissions. It has neither WRITE_SECURE_SETTINGS nor CHANGE_COMPONENT_ENABLED_STATE. With ro.control_privapp_permissions=enforce, any new privileged permission must be added to the on-device allowlist as well.

## Extension points
- (a) Push health to the iPhone over the live socket: send a new 'health' frame (codes, titles, fix text, romChanged, rom build) when the iPhone authenticates (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:352): In onAuthenticated(), after the existing protocol>=2 sends, send HealthReporter.problems(context) serialized like DiagnosticsReport line 104. Older iOS builds ignore it (GatewayConnection.swift:688 default: break). A new case is needed next to 'diagnostics_result' (GatewayConnection.swift:663), plus a @Published property and a ConnectionBanner-style warning (ContentView.swift:100/140). Document it in RedmiGateway/docs/PROTOCOL.md near line 177. This is the most reliable path because it fires every time the iPhone reconnects.
- (a) Push health to the iPhone through APNs when an audio-critical problem is found or ROM changed, even if no socket exists (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/service/HealthReporter.kt:61): Inside publish(), next to manager.notify, call ApnsSender.sendAlert(title, body, threadId='health', collapseId='health-<codes>'). ApnsSender.kt:98 is the API, and the alert shows on iOS without app changes (Notifier.swift:138). Caveats: post() hardcodes apns-expiration 0 (ApnsSender.kt:190), so a push right after boot with no network or an offline iPhone is lost. Add an expiration parameter or retry from the onAuthenticated path. alertsReady (ApnsSender.kt:59) must be true. Dedupe with a SharedPreferences 'last pushed codes' value so it is not sent on every START_STICKY restart.
- (a) Periodic re-check instead of once per service start (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/service/GatewayService.kt:285): reportHealth() is the single entry point, called from onStartCommand (line 134). You could add a handler.postDelayed loop (the service already uses its main-thread handler, e.g. line 132) or re-check on onClientCountChanged (line 355). vendorAudioFixPresent is cheap thanks to the lastModified cache (DiagnosticsReport.kt:50).
- (a) Make problems visible in diagnostics the PC pulls without the iPhone (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/journal/IphoneDiagnostics.kt:58): The health result currently goes only to DiagnosticsLog through CallManager.log (HealthReporter.kt:71). Writing a 'health' line with codes and the ROM build to a stable file lets adb pull or a remote fetch read it without anyone touching either phone.
- (b) ROM-changed warning: UpdateWatch already detects the change after reboot. Extend it to keep the previous and current build, push them to the iPhone, and include them in DiagnosticsReport (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/service/UpdateWatch.kt:28): check() overwrites last_build before anyone else can read it. To report 'ROM changed from X to Y' later (for example when the iPhone next connects), also store the previous build and a changedAt timestamp. DiagnosticsReport.kt:71 already reports the current rom block.
- (b) Pre-OTA warning: no code exists. A new watcher would have to detect a pending or downloaded update from the ROM's updater, or block it (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/service/GatewayService.kt:285): Nothing in the repo knows the updater's package name, state storage or settings. Options such as disabling the updater package (needs CHANGE_COMPONENT_ENABLED_STATE, not declared) or changing its auto-update preference (owned by the updater app, not Settings.Global) all need a device investigation first. See open_questions. Any new privileged permission must be added to the manifest (line 9 area), android/system/privapp-permissions-redmi-gateway.xml, RepairKit.allowlistPermissions (RepairKit.kt:56) and the apply.sh loop (RepairKit.kt:266). It must also reach the on-device /system/etc/permissions allowlist before the APK that requests it is installed, because of enforce mode.
- (c) iPhone TestFlight build age/expiry: carry it in client_status (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:66): Add a key such as 'buildDate' or 'tfExpires' to STATUS_KEYS, or it is silently dropped (lines 452-457). On iOS, add it to sendClientStatus (GatewayConnection.swift:1672). The value has to be written at build time: build-ios.yml:177 already uses PlistBuddy for CFBundleVersion, and the same step could write a build timestamp key. Android could then warn, through the health frame or APNs alert above, when the build is close to TestFlight expiry. Alternatively, a PC-side check through asc.mjs (teslim-kapisi.ps1:309-335) could read build expiry from App Store Connect.
- (c) Record the iPhone build at link time, which already happens (RedmiGateway/android/app/src/main/java/com/ilkay/redmigateway/server/GatewayWebSocketServer.kt:359): onAuthenticated already writes 'linked app=<ver> build=<build>' to iphone-diagnostics.log. Adding buildDate to the auth frame (iOS GatewayConnection.swift authenticate(), around line 826) and to peer fields (GatewayWebSocketServer.kt:105-106, 327-328) would give it per connection.

## Risks
- The owner never looks at the Redmi, but the only proactive health signal today is a Redmi notification (HealthReporter.kt:89). After an OTA the iPhone gets no warning unless someone taps 'Redmi'den rapor al' and reads raw JSON.
- If an OTA removes the app completely (only a /system/priv-app copy with no /data/app update), no Redmi code runs at all and nothing reports. Only the iPhone side, by noticing a long absence of the Redmi or of a heartbeat, could detect that.
- APNs pushes use apns-expiration 0 (ApnsSender.kt:190). A health push sent right after boot, before the network is up or while the iPhone is offline, would be dropped. post() retries only once on an IOException, and only when retry=true.
- romChanged is true on only one service start (UpdateWatch.check overwrites last_build). If that start's push fails, or the service restarts, the 'ROM güncellendi' context is lost.
- Adding a signature|privileged permission (e.g. WRITE_SECURE_SETTINGS, CHANGE_COMPONENT_ENABLED_STATE) to the manifest without first updating the on-device allowlist can fail the boot under ro.control_privapp_permissions=enforce (RepairKit.kt:52-54 comment). That would brick the gateway in the pocket. Three repo copies must also agree: the manifest, system/privapp-permissions-redmi-gateway.xml, and RepairKit.allowlistPermissions plus the apply.sh loop.
- The device's root status conflicts between sources. Memory (redmi-device-facts) says adb shell runs as root. OTA-ONARIM-20261028.md:34-35 says ro.debuggable=0 and no root after the OTA. RepairKit.kt:19 says the bootloader is locked, which the doc contradicts. Any design that assumes root or adb shell access on the running system is unverified.
- teslim-kapisi.ps1 default expected version is 2.0.13/213, so the gate reports KALDI unless called with explicit parameters.
- STATUS_KEYS lists 5 keys the iPhone never sends (callkit, audio, notify, ble, network). New keys must be added on both sides, or they are silently dropped.

## Open questions
- What is the exact package name of the ROM's OTA updater? Is it really org.lineageos.updater, given the '4.4.1-a16-...-community-ginkgo' build string? Where does it keep its auto-check/auto-install preference and its downloaded-update state? Nothing in the repo records this, and it needs `pm list packages` / `dumpsys package` on the device.
- Is the gateway app currently running from /system/priv-app directly, or from a /data/app update over the system copy? That decides whether an OTA leaves the app installed (and able to report) or removes it.
- Does adb on the running (non-recovery) system have root after the 28 Oct OTA? The memory note says yes as of September, the OTA doc says no root.
- Is the gateway APK platform-signed or debug-signed? Memory says debug-signed. This decides whether signature-only permissions are possible, or whether only the privileged route plus allowlist works for WRITE_SECURE_SETTINGS and CHANGE_COMPONENT_ENABLED_STATE.
- Does the system expose a readable signal for a pending or staged OTA (update_engine status, a system property, the updater's broadcast) to a priv-app with the permissions it already has? This is not verified anywhere in the repo.
- For TestFlight expiry: should the iOS build carry the date (PlistBuddy key in build-ios.yml), or should the PC-side asc.mjs read expiry from App Store Connect? Neither exists today.
- Should defaultDialer (not audioCritical) also be pushed to the iPhone? Today HealthReporter.publish ignores it, but DiagnosticsReport 'problems' includes it.
